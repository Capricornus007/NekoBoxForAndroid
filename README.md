# NekoBox_SF

**VPN-клиент для Android с гибкой маршрутизацией, автоматическим выбором серверов и поддержкой AmneziaWG.**

[**Скачать APK**](https://github.com/ISAIandCO/NekoBox_SF/releases) · [Сообщить о проблеме](https://github.com/ISAIandCO/NekoBox_SF/issues)

## Что это

NekoBox_SF позволяет выбирать, какие приложения и сайты открывать через прокси, а какие — напрямую. Можно подключаться к одному серверу, автоматически выбирать доступный узел из группы или переключать прямые маршруты на прокси при ограничениях сети.

Для подключения нужен **профиль сервера или ссылка на подписку** от вашего провайдера либо собственного сервера. В приложении нет предустановленных серверов. Требуется **Android 6 или новее**, root-доступ не нужен.

Проект основан на NekoBox for Android и форке starifly с поддержкой XHTTP. Интерфейс доработан по Material 3 Expressive; доступны светлая, тёмная, AMOLED и динамическая цветовые схемы.

## Возможности

- Маршруты по доменам, IP-адресам, приложениям и готовым спискам GeoIP/GeoSite.
- Автоматический переход прямых маршрутов на резервный прокси и возврат при восстановлении доступности.
- «Самый быстрый», «Водопад» и прокси-цепочки; фильтрация узлов по имени и протоколу, дополнительные проверки DNS и HTTPS.
- WireGuard и AmneziaWG, включая AWG 3.1; VLESS, VMess, Shadowsocks, Trojan, Hysteria и другие протоколы.
- Подписки с предпросмотром изменений и откатом предыдущего обновления.
- Резервные копии профилей, маршрутов и настроек, в том числе с паролем и через WebDAV.
- Диагностика DNS, соединений и маршрутов, сравнение узлов и живая статистика трафика.
- Автоматический выбор профиля и DNS при смене мобильной сети, Wi-Fi или Ethernet.

## Установка

Откройте [страницу выпусков](https://github.com/ISAIandCO/NekoBox_SF/releases) и выберите APK для своего устройства:

| Файл | Для каких устройств |
| --- | --- |
| `NB_SF-2.00-arm64-v8a.apk` | Большинство современных смартфонов и планшетов |
| `NB_SF-2.00-armeabi-v7a.apk` | Старые 32-битные ARM-устройства |
| `NB_SF-2.00-x86_64.apk` | 64-битные x86-устройства и эмуляторы |
| `NB_SF-2.00-x86.apk` | 32-битные x86-устройства и эмуляторы |

В следующих выпусках номер версии в имени файла меняется, обозначение архитектуры остаётся тем же. Если не знаете, что выбрать, обычно нужен **arm64-v8a**.

Android может запросить разрешение на установку из браузера или файлового менеджера. При первом подключении подтвердите системный запрос на создание VPN.

### Переход со старых версий на 2.00

> [!IMPORTANT]
> **Изменились имя пакета и ключ подписи.** Старый пакет `com.isaiandco.neko.debug` заменён на `com.isaiandco.neko`. Начиная с 2.00 используется новый личный ключ подписи, поэтому установка поверх прежних тестовых сборок с тем же именем пакета невозможна без переноса данных.

1. В старом приложении откройте **Инструменты → Бэкап** и экспортируйте профили, правила маршрутизации и настройки.
2. Сохраните копию **вне папки приложения**, например в «Загрузки». Убедитесь, что файл доступен; для зашифрованной копии сохраните пароль.
3. Если установлена прежняя сборка `com.isaiandco.neko`, удалите её после сохранения бэкапа и установите новую.
4. В новой версии откройте **Инструменты → Бэкап**, импортируйте файл и проверьте подключение.

Если старый и новый пакеты установились рядом, удаляйте старое приложение после проверки переноса. Дальнейшие обновления с тем же пакетом и ключом устанавливаются поверх новой версии с сохранением данных.

## Первое подключение

1. **Добавьте сервер.** В разделе **Конфигурация** доступен импорт из буфера обмена, файла или QR-кода. Для подписки создайте группу в разделе **Группы**, выберите тип «Подписка», укажите ссылку и обновите её.
2. **Выберите профиль** в списке конфигураций. Позже вместо отдельного сервера можно выбрать «Самый быстрый» или «Водопад».
3. **Проверьте список приложений** в **Настройки → Режим VPN для приложений**. Часть приложений из начального списка исключена из VPN; измените список под свои задачи.
4. **Включите подключение** и подтвердите запрос Android. Если нужный ресурс не открывается, воспользуйтесь разделом **Диагностика**.

GeoIP и GeoSite уже включены в APK: отдельно скачивать базы перед первым подключением не требуется.

## Как направляется трафик

Сначала действует выбор приложений, затем — маршруты для трафика, охваченного VPN.

| Трафик | Поведение начальной конфигурации |
| --- | --- |
| Приложение из списка обхода VPN | Использует обычное подключение Android; маршруты приложения к нему не применяются |
| Локальная сеть | Напрямую |
| Российские домены и IP из GeoSite/GeoIP | Напрямую, пока доступность подтверждается; при неудачной проверке — через выбранный прокси |
| Остальные адреса внутри VPN | Через выбранный профиль или группу |

Это начальные правила, а не определение гражданства сайта: принадлежность домена и адреса зависит от содержимого баз. Свои исключения можно добавить в разделе **Маршруты**. Порядок правил имеет значение: более высокое подходящее правило может перекрыть расположенные ниже. В меню есть проверка дублей и очевидных перекрытий доменных правил.

### Выбор приложений

В **Настройки → Режим VPN для приложений** можно выбрать:

- **Обход** — отмеченные приложения работают напрямую, остальные охватываются VPN.
- **Прокси** — VPN охватывает только отмеченные приложения.
- Отключение фильтрации — VPN охватывает приложения без этого разделения.

Доменные и IP-маршруты продолжают действовать внутри выбранного режима. После изменения списка перезапустите подключение, чтобы применились новые ограничения.

### Резервный прокси для прямых маршрутов

В **Настройках** найдите параметр **Резервный прокси для прямых маршрутов**. Опция проверяет контрольные сайты напрямую. Если нужное число сайтов недоступно, прямые маршруты переключаются на прокси; при восстановлении доступности возвращаются обратно.

Можно изменить контрольные адреса, интервал, число необходимых успешных ответов и число последовательных проверок перед переключением. Для отдельного маршрута доступны собственные варианты: наследовать общую политику, всегда идти напрямую или использовать выбранный резервный профиль.

**Контрольные сайты должны подходить вашей сети.** Если они доступны в белом списке оператора, успешная проверка сохранит прямой путь. Это общая проверка состояния сети; она не повторяет через прокси каждый неудачный запрос к произвольному сайту.

До подтверждения прямой доступности используется прокси. Локальная сеть остаётся прямой. В **Диагностике** видны результаты сайтов, время проверки и причина переключения.

## Группы серверов

| Тип | Как выбирается путь |
| --- | --- |
| **Самый быстрый** | Выбирает доступный узел с наименьшей измеренной задержкой |
| **Водопад** | Использует первый доступный вариант в заданном вами порядке |
| **Прокси-цепочка** | Последовательно проводит соединение через несколько выбранных узлов |

В «Самом быстром» доступны ручной список и динамический отбор по имени. Можно исключить нежелательные протоколы или оставить только выбранные; предпросмотр показывает итоговый список узлов.

Две дополнительные опции помогают отсеять серверы, которые отвечают на обычную проверку, но не подходят для работы:

- **Проверять DNS и HTTPS** — проверяет настроенный удалённый DNS и контрольный HTTPS-сайт через каждый узел.
- **Временно исключать сбойные узлы** — после трёх ошибок делает паузу перед следующей попыткой; пауза увеличивается от 30 секунд до 10 минут.

Эти опции включаются отдельно. После изменения параметров группы перезапустите активное подключение. Если один протокол в вашей сети работает нестабильно, его можно исключить из автоматического выбора, сохранив сами профили.

## Начальные настройки

Новые установки получают готовую базовую конфигурацию:

| Параметр | Значение |
| --- | --- |
| Режим | VPN с начальным списком приложений для обхода |
| Прямые маршруты | Локальная сеть, российские домены и российские IP |
| Резервирование прямых маршрутов | Включено; четыре контрольных сайта, для успеха нужны два ответа |
| Проверки доступности | Каждые 30 секунд при активном экране; для переключения и возврата достаточно одной завершённой проверки |
| Удалённый DNS | AdGuard DoH |
| Прямой DNS | Системный DNS Android |
| IPv6 | Включён |
| FakeDNS и маршрутизация DNS | Выключены |
| Обновление GeoIP/GeoSite | Каждые 72 часа |
| Автоматическое подключение после перезагрузки | Включено после начала использования VPN |
| Проверка TLS-сертификатов | Включена |

Начальные контрольные адреса — kernel.org, Cloudflare, Google и Firefox. Список исключённых приложений и правила можно менять. Для полного пользовательского JSON действуют его собственные настройки DNS и маршрутизации.

**Обновление приложения не заменяет сохранённую конфигурацию.** Импорт бэкапа восстанавливает выбранные данные, а явный сброс настроек или маршрутов возвращает соответствующую часть начальной конфигурации.

При выключенном экране, блокировке и Doze проверки узлов и контрольных сайтов приостанавливаются. Само подключение продолжает работать; после разблокировки проверки возобновляются. Статистика в фоне читается реже, накопленный объём сохраняется.

## Подписки, импорт и резервные копии

При ручном обновлении подписки приложение показывает добавленные, удалённые и изменённые узлы. В меню группы доступна **Предыдущая версия подписки** — откат последнего изменившего данные обновления. Обновление без изменений не стирает точку отката.

Поддерживаются распространённые подписки Shadowsocks, Clash/Clash Meta, v2rayN и узлы из sing-box. При импорте таких подписок извлекаются серверы; правила и политика исходного клиента автоматически не переносятся. Для подписки можно отдельно задать DNS сервера, HTTP-заголовки и HWID. В настройках приложения можно включить загрузки подписок и баз только через прокси.

Конфигурации WireGuard и AmneziaWG импортируются из INI, `vpn://` и поддерживаемых упакованных файлов. DNS, AllowedIPs и PersistentKeepalive сохраняются; применение импортированных сетевых параметров к выбранному одиночному профилю включается отдельной опцией.

В **Инструменты → Бэкап** можно сохранить профили, маршруты и настройки в файл или через WebDAV. Пароль включает шифрование копии; обычный JSON также поддерживается. Храните пароль отдельно: без него зашифрованный бэкап не восстановить. Для переноса используйте экспорт внутри приложения — базы с профилями исключены из автоматического системного резервирования Android.

Если неудачно изменили DNS или маршрутизацию, в **Настройках** есть действие **Вернуть предыдущие настройки сети**. Оно восстанавливает сохранённую точку, не заменяя остальные настройки и профили.

## Профили для разных сетей

В **Настройки → Профили для сетей** можно назначить разные профили подключения и DNS для мобильной сети, Wi-Fi, определённого SSID и Ethernet. Правило конкретного SSID имеет приоритет над общим правилом Wi-Fi.

Для определения SSID Android может потребовать точную геолокацию с доступом в фоне и включённую системную геолокацию. Если определение SSID недоступно, можно пользоваться общими правилами по типу сети. Сетевые переопределения DNS не переписывают основные настройки.

## Диагностика и помощь

Откройте **Диагностику** из бокового меню. Здесь можно посмотреть выбранный узел, состояние резервирования прямых маршрутов и результаты проверок DNS, TCP и TLS, а также сравнить до восьми серверов. Для WG/AWG доступна проверка прохождения пакетов разных размеров; она не меняет MTU автоматически.

Подробная история маршрутов и DNS собирается **только при уровне журнала debug или trace** и хранится в памяти за последние десять минут. Есть фильтры по приложению, домену и узлу. При большом потоке событий приложение сообщает о досрочном вытеснении старых записей.

| Ситуация | Что проверить |
| --- | --- |
| APK не устанавливается поверх старой версии | [Перенос данных при смене пакета и подписи](#переход-со-старых-версий-на-200) |
| VPN включён, но внешний IP не изменился | Список обхода приложений и прямые маршруты: для них это ожидаемо |
| Сайт не открывается или не определяется его IP | Проверки DNS и соединения в диагностике, доступность выбранного сервера |
| VLESS работает, а Hysteria — нет | Доступность UDP и ограничения вашей сети; при необходимости исключите Hysteria из автоматического выбора |
| Прямой маршрут не переключается на прокси | Результаты контрольных сайтов, выбранный порог и доступность этих сайтов в белом списке |
| Счётчик отличается от статистики Android | Приложение учитывает трафик сессии через прокси, без прямого трафика и служебных проверок |
| После ручной правки DNS или маршрутов связь пропала | Действие «Вернуть предыдущие настройки сети» либо восстановление своего бэкапа |

Для сообщения об ошибке откройте [Issues](https://github.com/ISAIandCO/NekoBox_SF/issues). Укажите версию приложения, версию Android, протокол, тип сети и шаги воспроизведения. Если нужен подробный журнал, временно включите **debug**, повторите проблему и сохраните журнал из раздела **Журналы**.

Перед публикацией проверьте содержимое отчёта. Ссылки подписок, пароли, приватные ключи и полный бэкап с личными серверами публиковать не следует.
