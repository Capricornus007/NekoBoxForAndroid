# sing-box 1.14 compatibility checkpoint

The default build still uses the tested starifly 1.12 compatibility core.
These patches preserve the in-progress port without selecting it for an APK.

* Upstream base: SagerNet/sing-box `v1.14.3`, commit
  `7054cac5124465ffdb145870d7c01885566711b1`.
* Existing protocol sources: starifly/sing-box
  `0b7a2fc2f2c33f754e5fe5a1bb3e0a4f610b6aa9`, with this application's
  AWG, balancing, traffic, DNS, diagnostics and XHTTP fixes applied.
* Native patch base: application commit
  `6855853982cfb93a9773dffc1858ecf9e6b8771d`.

In an isolated checkout of the application at the native base, check out the
upstream core in the sibling `sing-box` directory, retain the pinned `libneko`
and `wireguard-go` siblings, and apply:

```sh
git -C ../sing-box apply "$PWD/buildScript/lib/core/compat_114.patch"
git apply buildScript/lib/core/compat_114_native.patch
cd libcore
go test -tags=with_conntrack,with_gvisor,with_quic,with_wireguard,with_utls,with_clash_api -run '^$' .
go test -race -tags=with_conntrack,with_gvisor,with_quic,with_wireguard,with_utls,with_clash_api -run 'Test(WireGuard|InvalidAmnezia|XHTTP|SelectorTracks|IngressSession|Traffic)' .
```

The two commands pass at this checkpoint. The candidate uses the renamed,
maintained Juicity module (`github.com/exclavenetwork/sing-juicity` v0.3.1).
The AmneziaWG adapter retains the existing TCP/UDP path; it does not implement
upstream's new direct L3/ICMP WireGuard port.

Before activation: migrate legacy inbound/DNS JSON semantics, verify bootstrap
and IPv6 DNS behavior, complete lifecycle cleanup and traffic regression checks,
preserve custom QUIC congestion-window options, and compile Android bindings.
The complete native suite has not passed yet: DNS `strategy` rule actions cannot
be combined with modern query-type rules as generated by the current app.
There is no new APK for this checkpoint. Device/work-profile/Private DNS tests
also remain open; no ADB target is available in this environment.
